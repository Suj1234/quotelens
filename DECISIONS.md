- **2026-09-23 · Doc filenames.** CLAUDE.md refers to `docs/01_PRD.md` / `docs/02_FSD_TRD.md`; the files are `docs/01_PRD_Kill_the_Quote_Spreadsheet.md` / `docs/02_FSD_TRD_Kill_the_Quote_Spreadsheet.md`. Kept the files as delivered. Matters only when locating sections.
- **2026-09-23 · Next.js.** TRD §2 says 15.x (verify). `create-next-app@latest` gave **16.3.6** with React 19.2 and Tailwind **v4** (CSS-first config, no `tailwind.config`). Tokens live in `src/app/globals.css` (`:root` + `@theme inline`), which is how DESIGN.md's "tailwind.config theme extensions" maps to v4. Next 16 ships `AGENTS.md` with the rule to read `node_modules/next/dist/docs/` before writing Next-specific code; kept.
- **2026-09-23 · shadcn/ui.** CLI 4.21.0, style `radix-nova`, base Radix. `toast` is no longer offered for Radix projects → using **`sonner`**. shadcn CSS variables are mapped onto DESIGN.md tokens in `globals.css`; radii capped at 3/5/6px.
- **2026-09-23 · SheetJS.** npm `xlsx@0.18.5` has an unfixed high-severity advisory (prototype pollution / ReDoS) and we parse untrusted vendor files → installed **0.20.3 from `cdn.sheetjs.com`** (SheetJS's official distribution). Remaining `npm audit` item: `uuid@8` via exceljs (buffer path of v3/v5/v6 only; exceljs uses v4) — not reachable.
- **2026-09-23 · Fonts.** DESIGN.md §1.3 says self-host woff2 in `/public/fonts`. Using `next/font/google` (IBM Plex Sans 400/500/600, Mono 400/500), which downloads at build time and serves from our own origin — same outcome, no manual font files.
- **2026-09-23 · Theme.** DESIGN.md's `localStorage["ql-theme"]` + `data-theme` on `<html>` (prototype's mechanism); no stored value = follow OS. Tailwind `dark:` variant bound to `[data-theme="dark"]`.
- **2026-09-23 · `@types/node`.** Scaffold pinned `^20`; vitest 5 peers need ≥22. Runtime is Node 22 → `@types/node@^22`.
- **2026-09-23 · `server-only` in scripts/tests.** `tsx` scripts run with `--conditions=react-server` so `server-only` resolves to its empty module; vitest aliases it to a stub.
- **2026-09-23 · Supabase API keys (P0-T2, checked supabase.com/docs/guides/api/api-keys).** Legacy `anon`/`service_role` JWT keys are deprecated by end of 2026; new keys are `sb_publishable_…` / `sb_secret_…`. A secret key works in `createClient` exactly like service_role and bypasses RLS; Supabase rejects it from browsers (User-Agent check). We keep the TRD env names — `SUPABASE_SERVICE_ROLE_KEY` may hold either the legacy service_role JWT or an `sb_secret_` key.
- **2026-09-23 · Supabase Storage API (P0-T2).** Docs pages for the JS reference moved (404); verified against installed `@supabase/storage-js@2.117.1` typings: `storage.from(bucket).createSignedUrl(path, expiresInSeconds, { download?, transform? })` → `{ data: { signedUrl } }`; `upload(path, body, { contentType, upsert })`; `createBucket(id, { public })`. Signed URLs use 3600 s (TRD §5: 60 min).
- **2026-09-23 · Migrations.** `0001_init.sql` / `0002_views.sql` are extracted **verbatim** from TRD §6.1–6.21 (awk over the code blocks). Additions, each marked in the file: (a) dropped nothing, removed `create extension pgcrypto` — `gen_random_uuid()` is core since PG13; (b) RLS enabled on every table with no policies + privileges revoked from `anon`/`authenticated`, so a leaked anon/publishable key reads nothing (service role bypasses RLS, so the app is unaffected); (c) views set `security_invoker = true`; (d) `run_readonly_query` gets `search_path = public`, execute revoked from public/anon/authenticated and granted to `service_role` (TRD §6.21 asks for this). (e) `0003_storage.sql` creates the four private buckets via `storage.buckets` (idempotent). Validated locally on PGlite (embedded PG): all apply; read-only function blocks writes even mid-transaction. Applied via: **SQL editor** (no Supabase MCP in this session, no psql) — `npm run db:migrate` prints the instruction; `npm run db:check` verifies.
- **2026-09-23 · Known risk for P4.** `run_readonly_query` is `security definer` (runs as owner) so it can read any table, incl. `users.password_hash`. The SQL guard (P4-T1) must allow only the `v_*` views. Upgrade path if needed: a dedicated `query_reader` role granted SELECT on views only, and the function owned by it.
- **2026-09-23 · Scripts env.** `tsx --env-file-if-exists=.env.local` (Node 22 flag) instead of dotenv.
